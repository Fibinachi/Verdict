Troubleshooting

This page covers common issues you may encounter while using Verdict and their solutions.

Build Fails

Symptoms: dotnet build returns errors.

Possible causes and solutions:

  • .NET 9 SDK not installed — Verify that .NET 9 SDK is installed by running dotnet --version. If not installed, download from dotnet.microsoft.com.
  • Missing dependencies — Run dotnet restore to restore NuGet packages before building.
  • Build artifacts conflict — Run dotnet clean followed by dotnet build to start fresh.
  • Syntax errors — Check the error output for specific file and line references. Ensure you're using C# 12+ features correctly.

LLM Not Responding

Symptoms: Agent Chat, evidence analysis, or other AI features return no response or timeout.

Possible causes and solutions:

  • No model configured — Go to Settings > Model Settings and add at least one model.
  • Invalid API key — Verify your API key is correct and has not expired. Use the Test Connection button to check.
  • Network issues — Ensure you have internet access if using cloud providers (OpenAI, Anthropic, etc.).
  • Rate limiting — Some providers impose rate limits. Wait a moment and try again.
  • Model not assigned to agent — Check that the agent has a model selected in its profile settings.

Models Not Appearing

Symptoms: No models show up in the Model Settings window or agent profile dropdown.

Possible causes and solutions:

  • No models added — Click the Add Model button in Model Settings to configure a model.
  • Provider not configured — Ensure you've selected a provider and entered all required fields.
  • Ollama not running — If using Ollama, ensure the Ollama service is running locally. Run ollama serve in a terminal.
  • Provider discovery failed — Check the ProviderDiscoveryService logs for errors.

Jurors Not Forming Opinions

Symptoms: Juror sentiment and verdict lean remain at default values and do not change.

Possible causes and solutions:

  • No LLM model configured — Juror behavior requires an active LLM model to process trial events and update opinions.
  • No evidence submitted — Jurors need evidence and arguments to form opinions. Submit evidence and use the Stage menu to progress through trial phases.
  • Memory decay too aggressive — The default decay factor is 0.95. If opinions seem too static, check that trial events are being created properly.
  • Juror not generated properly — Try deleting the juror and using Generate Likely Juror or Generate Jury to create a new one.

Application Crashes

Symptoms: Verdict closes unexpectedly or becomes unresponsive.

Possible causes and solutions:

  • Insufficient memory — Close other applications to free up RAM. Verdict requires at least 4 GB.
  • Corrupted case file — Try opening a different case file to isolate the issue. Backup your .jur files regularly.
  • LLM timeout — A slow or unresponsive LLM provider can cause the UI to freeze. Check your network connection.
  • Update to latest version — Ensure you're running the latest build. Run git pull and rebuild.

Evidence Not Processing

Symptoms: Submitted evidence files are not analyzed or do not appear in the Exhibit List.

Possible causes and solutions:

  • Unsupported file type — Ensure the file is one of the supported types: PDF, TXT, DOCX, RTF, JPG, JPEG, PNG, GIF, BMP.
  • File is corrupted — Try opening the file outside of Verdict to verify it's not damaged.
  • No LLM configured — AI analysis requires an active model. Configure a model in Settings > Model Settings.
  • File too large — Very large files may take longer to process or exceed provider limits.
Still having issues? Check the TODO.md file in the project root for known issues and planned improvements. You can also review the test harness in Tests/TestHarness.cs for verification of core components.
